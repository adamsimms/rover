# Adaptation checklist & binder index

How to turn the [reusable core](package.md) into one submission. Per-call Issues own the final submit checklist; this page is the shared pattern.

## Per-call adaptation (do this for each apply Issue)

1. Read the Issue summary + submission checklist.
2. Pull **universal** texts from package #28 (statement, bio, CV, portfolio, facts/timeline as needed).
3. Complete **call-specific** writing under that apply Issue (proposal, why-this-place). Banff lives on [#55](https://github.com/adamsimms/rover/issues/55); Eastern Edge Studio on [glowberry#54](https://github.com/adamsimms/glowberry/issues/54); Eastern Edge Main Gallery on [dreamberry#49](https://github.com/adamsimms/dreamberry/issues/49); The Rooms on [glowberry#57](https://github.com/adamsimms/glowberry/issues/57); OBORO on [dreamberry#43](https://github.com/adamsimms/dreamberry/issues/43) (includes tech + budget).
4. Optional: copy drafts into `Sketchpad/residencies/calls/<slug>.md`; for heavy forms, keep a print-ready `*-application-responses.md` beside the research call file.
5. Cut to word limits; fill form; check off the Issue checklist; note confirmation on the Issue. Reuse patterns in [application-craft.md](application-craft.md).
6. Do not paste full essays into GitHub Issues.
7. **Promote:** copy as-submitted texts into [submissions/](submissions/)<slug>/ (redact phone, street address, restricted amounts); link from this binder and [submissions/README.md](submissions/README.md). Dual-write apply-wave status to the vault Residencies MOC. Do not treat Sketchpad as a second status board.
